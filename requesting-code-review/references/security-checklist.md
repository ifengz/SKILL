# Security and Reliability: Targeted Review

Read when the change touches a trust boundary, authentication/authorization, input/output, network or file access, secrets, dependencies, CI/build configuration, resource limits, shared writes, destructive operations, or a safety guard. Also read it when untrusted model or tool output reaches a sensitive sink. Apply only the relevant rows. This is not a full security audit and does not authorize live attacks, credential access, installs, or production requests.

## Evidence Before Findings

Trace `entry -> attacker-controlled value or competing actor -> validation/authorization -> sensitive operation -> observable impact`. Include middleware, database constraints, framework escaping, deployment restrictions, and other existing defenses before declaring a gap. Cite the concrete source/sink and the failed invariant. Distinguish a source-proven path from an executed reproduction; neither an API name nor a scanner match alone proves exploitability.

| Surface | Checks and evidence to collect | Countercheck before reporting |
| --- | --- | --- |
| Authorization / IDOR | Resource ownership, account/tenant key, role and action checked on server for reads, writes, exports, batch and nested resources. Trace an actor requesting another actor's resource. | Authentication alone is insufficient; authorization may legitimately live in a shared guard or scoped query. Read that implementation. |
| SQL / NoSQL / command injection | Trace input into query operators, SQL identifiers/values, shell strings and interpreter options. Require parameterization for values and explicit allowed identifiers/options where needed. | Bound SQL values are not concatenated SQL; an argument array avoids shell expansion but may still permit option injection. Do not report by string pattern alone. |
| XSS / unsafe rendering | Determine HTML, attribute, URL, script or DOM context; follow stored and reflected data into raw rendering. Check sanitization and allowed URL schemes in that context. | Normal framework text escaping can close the path; raw HTML needs separate evidence. CSP is defense in depth, not a substitute for correct handling. |
| SSRF / outbound requests | User control of scheme, host, port, resolved addresses and redirects; access to internal/metadata services; network egress restrictions. Validate each hop when redirects are allowed. | A fixed server-controlled URL is different from arbitrary user input. Host string checks alone may not address redirects or DNS changes. Missing allowlist alone is not proof of an exploitable path. |
| Files / uploads / archives | Canonical destination containment, symlinks, archive traversal, overwrite permissions, upload size/type, execution and serving location. Check the final operation, not just filename cleanup. | Lexical prefix matching may accept sibling paths; normalization alone does not settle symlink races. Evaluate the actual storage API and filesystem permissions. |
| Sessions / tokens / browser requests | Signature and allowed algorithm, issuer/audience/expiry as required by token contract; cookie flags, session rotation, logout/revocation; CSRF on cookie-authenticated mutations; exact credentialed CORS origins. | Decoding is not verification. CORS is not authorization or general CSRF protection. Cross-origin wildcard-plus-credentials is rejected by browsers; establish the actual accepted request path rather than assuming it leaks. |
| Secrets / PII / crypto | Trace sensitive values to client bundles, logs, exceptions, URLs, telemetry and stored artifacts. Check key/nonce handling, approved crypto primitives and authenticated encryption where relevant. | Redact evidence. A placeholder is not a live secret; a non-security checksum is not password hashing. Do not fetch or print credentials to prove a finding. |
| Deserialization / dynamic execution | Untrusted data reaching eval, executable templates, unsafe object deserialization or prototype-sensitive merges; privilege of the runtime. | A data-only parser is not automatically executable. Identify the unsafe operation and reachable input. |
| Dependencies / build supply chain | Exact resolved version and source, registry boundaries, lockfile/integrity changes, install scripts, client/server exposure; applicable advisory and affected range when claiming a known vulnerability. | A manifest range with a committed lockfile is not inherently a vulnerability. Outdated does not mean vulnerable. Report advisory lookup unavailable rather than inventing a CVE. |
| Resource limits | Untrusted input size, decompression, regex cost, N+1 or repeated queries, unbounded result sets, pagination, retries, timeouts, recursion and connection lifetime; likely cost and reachable caller. | A missing local timeout may be covered by a bounded outer request. Do not demand rate limiting or caching without a concrete resource or abuse scenario. |
| Concurrency / TOCTOU | Identify shared state and concurrent actors. Check transactions, unique constraints, compare-and-set, isolation, atomic increments, idempotency and recovery after partial failure. | Absence of a distributed lock is not itself a bug. A unique constraint may prevent duplicate rows, but does not necessarily prevent duplicate external side effects; inspect ordering and error handling. |
| Removed or weakened guard | Validation, authorization, rate limit, timeout, escaping or bounds check removed or narrowed; whether the enclosing contract still holds and whether a downstream layer enforces it. Require a negative test for the removed protection. For a removed guard, read the introducing commit; a guard added for a bug, CVE, or incident survives until the cause is shown gone (see [removal safety](removal-safety.md)). | A guard may be redundant with a database constraint, framework escaping or caller check; read the actual path before reporting. A removed test is not proof that the protection is gone. |
| CI / build configuration | Workflow token permissions, third-party actions pinned to a commit SHA, untrusted `${{ }}` values interpolated into `run:`, cache/artifact integrity, secrets in logs. | A read-only workflow or pinned action may close the path; a scanner hit alone is not exploitability. Check the actual event and permission scope. |
| Destructive operations / bulk deletion | Matcher breadth in every primary and fallback branch, protected-path coverage at the new entry point, confirmation, and whether the guard lives inside the deletion primitive. Ask for the narrowest evidence authorizing deletion. | Exact identifiers and paths can authorize; display names, vendor prefixes and user labels cannot safely authorize neighboring deletion. A dry-run may be sufficient for a local private helper. |
| Non-atomic writes / partial failure | Writes to user-owned paths (`>`, `tee`, `curl -o`, truncate-then-write), staging via sibling temp file, rename/commit point, signal/interrupt handling, idempotent recovery. | A transactional API or atomic rename may close the path; append-only logs or in-memory buffers may legitimately accept partial content. |
| Untrusted model or tool output | LLM, retrieved document or tool output reaching shell, filesystem, database, HTML or an authorization decision; prompt injection; whether the agent has independent authorization for the sink. | A typed schema, read-only sink or human approval may close the path; the model name alone is not a vulnerability. |

## Calibration Examples

- **Report:** `findOrder(id)` followed by mutation, with no caller guard or owner-scoped query, lets an authenticated user alter a different owner's order. Cite both read and write paths plus the permission contract.
- **Do not report SQL injection:** a search term is passed as a bound value and the driver performs binding. A malicious-looking test string is data, not an exploit. Inspect dynamic identifiers separately.
- **Report concurrency risk when proven:** two callers both pass a stock check and then decrement without an atomic condition, allowing negative stock. A missing mutex by itself is not the finding; the violated stock invariant is.
- **Unverified, not cleared:** the changed outbound request follows user-controlled redirects but the network policy is unavailable. Explain the known path and missing constraint; do not claim a reproduced internal-service access or that the system is safe.

For ambiguous findings or severity, use [review calibration](review-calibration.md). Base severity on reachable impact and prerequisites, not the checklist category.

## External Reference Points

These are navigation references, not bundled standards, automatic compliance gates, or a claim of current certification. Consult the relevant current section only when needed and permitted. Record the version/section actually used; if unavailable, state that limit and use local evidence.

- [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/): organize application security requirements; select controls appropriate to the actual surface.
- [OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/): implementation guidance for authorization, injection, SSRF, CSRF, sessions and secrets.
- [CWE](https://cwe.mitre.org/): describe an established weakness mechanism; a CWE mapping does not prove a reachable vulnerability.
- The project's framework, database and driver documentation at its actual version: verify escaping, parameter binding, transactions and isolation assumptions. Do not substitute latest-version behavior for the deployed version.

Use a dedicated security workflow only when requested or when the risk requires a separately agreed scope. Do not silently start another agent tree or a broad scan from this checklist.
